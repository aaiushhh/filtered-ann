# subramanya2019diskann — DiskANN: Fast Accurate Billion-point Nearest Neighbor Search on a Single Node
Authors / Year / Venue / DOI: Jayaram Subramanya, Suhas, Devvrit, Fnu, Simhadri, Harsha Vardhan, Krishnawamy, Ravishankar, Kadekodi, Rohan / 2019 / NeurIPS 2019 / none
Status: PUB
PDF: papers/subramanya2019diskann.pdf   Read fully: yes

## Problem addressed (p.)
Approximate nearest neighbor search (ANNS) on billion-point datasets on a single commodity workstation; overcoming the unsustainable DRAM footprint of all-in-memory graph indices (HNSW, NSG) and the low 1-recall@1 (plateauing at ~50%) of compression-based inverted index methods (FAISS, IVFOADC+G+P) by serving graph indices directly from solid-state drives (SSDs) (p. 1–2).

## Method (core idea in ≤5 sentences) (p.)
DiskANN introduces Vamana, a single-layer directed proximity graph built via two passes with a `RobustPrune` procedure using distance threshold $\alpha \ge 1$ to deliberately add long-range shortcut edges and minimize graph diameter (p. 3–5). To index billion-scale datasets within 64 GB DRAM, DiskANN partitions data into overlapping clusters ($k=40, \ell=2$), constructs Vamana indices independently in DRAM, and takes the union of edges into a single disk index (p. 6, 8). At search time, Product Quantization (PQ) compressed vectors (e.g. 32 bytes/point) are cached in DRAM to guide a beam search ($W=2,4,8$), while full-precision vectors and adjacency lists reside on SSD (p. 6–7). Each SSD read fetches both the out-neighbors and the 4KB-aligned full-precision coordinates of visited nodes, piggybacking exact distance re-ranking without extra I/O operations (p. 6–7). An initial DRAM cache of nodes within $C=3$ or 4 hops of the medoid start node further minimizes sequential SSD round-trips (p. 7).

## Complexity / theoretical claims
- Statement, assumptions, theorem number, page:
  - If out-neighbors of every point $p \in P$ are selected via `RobustPrune(p, P \ {p}, \alpha, n-1)` with $\alpha > 1$, then `GreedySearch(s, p, 1, 1)` starting at any $s$ converges to $p$ in $O(\log n)$ steps (§2.2, p. 4).
  - Construction of this exact graph requires $\tilde{O}(n^2)$ time; hence practical Vamana prunes over candidate sets $V$ generated by greedy search passes (§2.1–2.2, p. 3–4).
  - Theorem number: none stated (empirical algorithm with asymptotic motivation) (§2.1–2.2, p. 3–4).

## Filter type and selectivity regime handled (p.)
not stated (pure Euclidean vector similarity search without metadata predicates or filter constraints) (p. 1–9).

## Index structure used (HNSW / IVF / Vamana / other) (p.)
Vamana (single-layer directed graph) stored on SSD, with in-memory PQ-compressed vectors and DRAM caching of early hops (p. 1, 3–7).

## Datasets, baselines, metrics (Table N)
- Datasets (§4.1, 4.3, p. 8):
  - In-memory datasets: SIFT1M (1M, 128d), GIST1M (1M, 960d), DEEP1M (1M, 96d).
  - Billion-scale datasets: ANN_SIFT1B bigann ($10^9$ points, 128 uint8), DEEP1B ($10^9$ points, 96d float).
- Baselines (§4.1, 4.4, p. 8–9): HNSW, NSG, FAISS, IVFOADC+G+P (with 16-byte and 32-byte OPQ codebooks), Zoom.
- Metrics (§1, p. 1; §4.1–4.4, p. 8–9): 1-recall@1, 5-recall@5, 100-recall@100, query latency (ms), QPS (queries/sec), number of sequential disk hops, index build time (days/seconds).

## Key results (numbers exactly as reported, with Table/Fig locator)
- On SIFT1B, DiskANN serves > 5000 QPS with < 3 ms mean latency and 95%+ 1-recall@1 on a 16-core workstation with 64 GB RAM, whereas FAISS and IVFOADC+G+P plateau around 50% 1-recall@1 (Abstract, p. 1; §4.4, p. 9).
- Single-shot Vamana index on SIFT1B reaches 98.68% 1-recall@1 at < 5 ms latency, taking ~2 days to construct on a 1792 GB RAM VM with average degree 113.9 (§4.3, p. 8–9; Fig. 2(a)).
- Merged Vamana index on SIFT1B builds in ~5 days on a 64 GB workstation, generating a 348 GB SSD index with average degree 92.1, reaching > 95% 1-recall@1 in < 3.5 ms (within 20% latency of single index) (§4.3–4.4, p. 8–9; Fig. 2(a)).
- While IVFOADC+G+P-16 plateaus at 37.04% 1-recall@1 and IVFOADC+G+P-32 reaches 62.74%, DiskANN reaches 100% 1-recall@1 with the same memory footprint (§4.4, p. 9).
- On in-memory DEEP1M, Vamana index construction takes 129s, outperforming HNSW (219s) and NSG (480s) on workstation z840 (§4.1, p. 8).

## Limitations (author-stated vs. observed)
- Author-stated: Constructing the merged Vamana index for SIFT1B takes ~5 days on a 64 GB RAM machine (§4.3, p. 8); saturating SSD queue depth causes queue backlog and read latency spikes over 1 ms, requiring the SSD to run at 30–40% load factor with low beam widths ($W=2,4,8$) (§3.3, p. 7); merged indices traverse slightly more hops than single-shot indices due to partition edge boundaries (§4.3, p. 8–9).
- Observed: Pure vector similarity search without support for metadata predicate filtering (addressed in subsequent work, Filtered-DiskANN / Gollapudi et al. 2023).

## Relevance to our project (≤3 sentences; which part: filter structure / HNSW traversal / cost model / baseline to beat)
DiskANN introduces the Vamana graph construction and $\alpha$-pruning rule that serves as the dominant SSD-resident indexing paradigm and the direct predecessor to Filtered-DiskANN. Its characterization of graph diameter, beam search hop expansion, and I/O-compute tradeoffs provides essential baseline mechanisms for evaluating how predicate filtering affects graph search efficiency.
Novelty check: Novelty check: no (p. 1–9; purely vector similarity search without metadata predicates or probabilistic membership filters).
